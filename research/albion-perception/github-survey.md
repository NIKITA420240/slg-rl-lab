# Распознавание экрана Albion Online: обзор публичных проектов

Дата проверки: 2026-10-04.

Вопрос: есть ли опубликованный код, данные и модели для восстановления наблюдаемого состояния Albion по изображению экрана?

## Результат и метод проверки

Да: найдены независимые реализации детекторов ресурсов, культур и элементов интерфейса, а также OCR. Полного проверенного решения для всех игровых экранов среди изученных проектов нет.

Проверены README, отдельные исходники, рекурсивные деревья файлов и метаданные GitHub API, связанные страницы датасетов Roboflow. Наличие кода и файлов проверено непосредственно; совместимость с текущим клиентом, качество и скорость на нашем компьютере не измерялись. Чужой код и веса не запускались. Дата push ниже — поле GitHub `pushed_at`, а не доказательство сопровождения модели.

## Наиболее полезные находки

### Общий детектор и данные a-Fig

[objectFinder.py](https://github.com/a-Fig/Automated-Game-Bot/blob/main/objectFinder.py) загружает пять моделей через `inference.get_model`: общую, способности, препятствия, индикатор загрузки и низкое здоровье. Для загрузки предусмотрены ключи Roboflow. Это не означает, что каждый кадр обязательно отправляется в облако: локальный режим и получение артефактов нужно проверить отдельно.

README называет YOLO11, но [страница общей модели](https://universe.roboflow.com/albion-edu-workspace/albion_detector-l4o1a) указывает Roboflow 3.0 Object Detection (Fast). Архитектура YOLO11 непосредственно не подтверждена.

Публичный датасет содержит 2 768 изображений и 11 классов, включая `tree`, `player`, `stone`, `fiber`, `hide`, `mob`, `ore`, `silver`, `red`. Для данных указана CC BY 4.0. Семантика `red` и остальных необычных названий требует просмотра разметки. Страница сообщает mAP@50 85%; это результат платформы, не наше измерение.

[Версия 5](https://universe.roboflow.com/albion-edu-workspace/albion_detector-l4o1a/dataset/5) содержит 13 299 примеров после генерации, включая аугментации: train 12 306, validation 600, test 393. Не следует трактовать этот объем как 13 299 независимо снятых кадров.

Также опубликованы [сегментация препятствий](https://universe.roboflow.com/albion-edu-workspace/obstacle_instance_detection) и [детектор состояний способностей](https://universe.roboflow.com/albiondetector/spell_detector). Это кандидаты для следующих этапов, после проверки общего детектора.

### Минимальный пример Spring-0

[train.py](https://github.com/Spring-0/yolov8-albion-online-object-detection/blob/development/train.py) обучает YOLOv8s. [bot.py](https://github.com/Spring-0/yolov8-albion-online-object-detection/blob/development/bot.py) показывает цепочку скриншот → предсказания, но также выполняет действия мышью; его нельзя считать чистым модулем наблюдения.

Путь загрузки весов в скрипте не совпадает с размещением файла в репозитории без настройки рабочей директории. Связанный [датасет v2](https://universe.roboflow.com/tinker-abus7/albion-copper-recognition/dataset/2) содержит всего 12 изображений: 10 train, 2 validation, 0 test. Он подходит для учебной проверки конвейера, но не подтверждает устойчивую детекцию на разных сценах. Для данных указана CC BY 4.0.

### Остальные варианты

У Michelprogram полезен [модуль детекции](https://github.com/Michelprogram/albion-gathering-bot/blob/main/Application/Albion/detection.py). Связанный [AlbionGathering](https://universe.roboflow.com/albiononline-c8fxi/albiongathering) содержит 276 изображений, 9 классов и указание CC BY 4.0. Загрузка готовых локальных весов из самого репозитория не подтверждена.

У flan6 [Detection.py](https://github.com/flan6/ml-cv-bot/blob/master/Detection.py) использует OpenCV DNN и YOLOv4-tiny. Классы: фасоль, капуста, морковь, кукуруза, картофель, тыква, репа, пшеница. По README захват окна рассчитан на Linux, поэтому для нашего Windows-клиента потребуется отдельный захват.

У LearnCodeByGaming [009_bot/detection.py](https://github.com/learncodebygaming/opencv_tutorials/blob/master/009_bot/detection.py) использует `CascadeClassifier`. [Windows-захват](https://github.com/learncodebygaming/opencv_tutorials/blob/master/009_bot/windowcapture.py) полезен как читаемый пример. [MIT-лицензия](https://github.com/learncodebygaming/opencv_tutorials/blob/master/LICENSE.md) присутствует. Старый одноклассовый детектор годится для сравнения методов.

У Avalon Atlas проверены [OCR-документация](https://github.com/Pililink/Avalon-Atlas/blob/main/docs/OCR.md), [ocr_service.rs](https://github.com/Pililink/Avalon-Atlas/blob/main/src-tauri/src/services/ocr_service.rs) и [capture.rs](https://github.com/Pililink/Avalon-Atlas/blob/main/src-tauri/src/utils/capture.rs). Это пример локального чтения текста и сопоставления с каталогом названий, а не распознавания всех объектов мира.

Дополнительный узкий пример: [StreamOfMindSoup/albion-portal-screenshot-ocr](https://github.com/StreamOfMindSoup/albion-portal-screenshot-ocr), Tesseract.js для подсказок порталов. README ограничивает вход английским интерфейсом и 1920×1080. Не является общим детектором.

## Оценка источников

- Исходники и дерево GitHub: высокая уверенность в наличии интерфейсов и артефактов; работоспособность без запуска не доказана.
- README: заявления авторов; версии моделей, лицензии и комплектность сверены с кодом. Найденные расхождения отмечены выше.
- Roboflow: первичный источник опубликованной разметки и метрик. Метрики требуют воспроизведения на отдельной тестовой выборке нашего клиента.
- Повторение описаний в поисковой выдаче не считалось независимым подтверждением качества.

## Рекомендация для нашей задачи

Начать с данных общего `albion_detector`, изучить изображения, классы и качество разметки. Затем реализовать собственный небольшой конвейер на Python: сохраненный кадр → объекты с классом, рамкой и уверенностью → изображение с разметкой и JSON. Использовать uv, Hydra/OmegaConf и loguru согласно AGENTS.md.

Для первого эксперимента оставить классы персонажа и ресурсов. Небольшую YOLO обучать или дообучать на пригодной публичной разметке и наших кадрах; сравнить с доступным готовым детектором, если условия получения весов позволяют. Оценивать precision/recall по классам, ложные срабатывания на пустых кадрах и задержку обработки. Тестовые сессии отделять от обучающих до извлечения кадров и аугментаций.

После проверки объектов добавлять OCR текста интерфейса, показатели здоровья/груза, сегментацию и временное отслеживание. Наличие рамки `tree` само по себе не доказывает, что дерево сейчас доступно для добычи; это отдельный атрибут состояния и отдельная проверка.

Следующий конкретный эксперимент: зафиксировать классы, проверить доступность экспорта выбранного датасета и собрать независимые кадры текущего PC-клиента. Нужный результат первого этапа — измеренное качество распознавания на сохраненных изображениях.
